# 跨项目开发与联调流程

1. 在工作区确认目标与改动范围，读双方 AGENTS、需求和当前状态，分别检查 Git 现场。
2. 需要最新集成代码时先查看 workspace.py sync 计划；只有干净 main 才更新。开发分支保留原状，不能为“最新”覆盖未提交修改。
3. 写清标准版本、角色、方向与适用条款；定义预期时序、输入、失败和资源回收。先判断标准要求还是产品策略，不能以对端实现作为唯一依据。
4. 单边缺陷在所属仓库修复与验证；双方变化分别提交，报告先后关系，保持中间状态可诊断。跨仓库提交不具备原子性，必要时使用明确兼容窗口。
5. 先跑双方独立测试，再做最小正常流程，按[场景](scenarios.md)逐项扩展。报文成功、设备状态、媒体成功分别观测。
6. 报告使用[模板](../templates/validation-report.md)，附双方准确 SHA、工作区是否 dirty、配置摘要/媒体 hash、拓扑、命令、时间与原始证据定位。dirty 运行只能作诊断，正式报告应使用干净可恢复提交。
7. 缺陷回写所属产品的测试和解释；共同配置或标准歧义在工作区记录。用户事项集中登记，未实现部分由 Agent 继续，不要求用户代测不存在的功能。

双方版本只记录于当次证据，随后继续跟随 main，不引入组合锁文件。双方互通、第三方互通、安全产品验收和容量测试是不同证据；不能互相替代。
