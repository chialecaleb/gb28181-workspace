# 工作区需求

工作区服务于同一开发者维护两个独立国标产品，负责跨项目知识、资料、联调和 Agent 工作入口，不提供业务运行时。

| 编号 | 要求与验收 |
| --- | --- |
| WS-R-001 | 三个独立 Git 远程，父仓库忽略产品目录；Git 树中不得存在子仓库源码/gitlink |
| WS-R-002 | 始终跟随各仓库 main 最新实现，不维护组合锁；更新只允许干净 main 快进，不破坏本地工作 |
| WS-R-003 | 单产品在本仓库开发，跨产品在工作区协调；规则显式读取，产品单独 clone 可开发 |
| WS-R-004 | 用户决定、外部配置和人工检查只维护一份 USER-ACTIONS，产品入口只导航 |
| WS-R-005 | Agent 连续完成规划、实现、测试与自审；默认不要求多 Agent，不把常规开发推给用户 |
| WS-R-006 | 原始标准集中保存，搬迁逐文件哈希一致；保留 OCR 配图和已有条款核对历史 |
| WS-R-007 | 两个产品独立维护协议解释、代码、测试与发布，不能通过私有 API 互相依赖 |
| WS-R-008 | 联调记录实际双方 SHA、环境和结果，用于复现证据，不用于约束后续版本更新 |
| WS-R-009 | main 经 PR、必需 CI、线性历史保护，禁止强推/删除；单维护者 0 个强制审批 |
| WS-R-010 | 工具、文档门禁和规则在本地与 CI 可运行；未实现能力不得标通过 |

不在本轮实现 SIP/媒体/业务应用，不改变两个产品原有完整标准功能目标。许可证、正式分发和真实测试环境集中记录，不阻断当前可自动完成的基础设施工作。
